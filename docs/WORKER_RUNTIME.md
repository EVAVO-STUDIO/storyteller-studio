# Private Worker Runtime

The Storyteller worker is a dedicated non-HTTP process. It composes the durable generation queue, immutable generation material, provider adapters, lease heartbeat, private object storage and artifact registry without exposing execution controls through the web application or operator API.

## Disabled by default

`STORYTELLER_WORKER_MODE` defaults to `disabled`. In disabled mode the process does not evaluate queue paths, provider credentials or execution settings and does not create persistence directories.

Enabled modes are:

- `once` — process available work until the queue is idle, then stop;
- `continuous` — keep polling until a process signal requests shutdown.

## Fail-closed storage

The initial runtime supports only one isolated host using the existing file-backed contracts. Enabled mode requires:

- `STORYTELLER_QUEUE_DRIVER=file`;
- `STORYTELLER_ARTIFACT_DRIVER=file`;
- a private `STORYTELLER_DATA_DIR`;
- a valid worker identity and verifier identity.

Production additionally requires all three explicit acknowledgements:

- `STORYTELLER_FILE_QUEUE_SINGLE_HOST=true`;
- `STORYTELLER_FILE_ARTIFACT_STORE_SINGLE_HOST=true`;
- `STORYTELLER_FILE_WORKER_SINGLE_HOST=true`.

The acknowledgements do not make file persistence distributed. They prevent an accidental serverless or multi-instance deployment from presenting local locks as cross-host coordination.

## Isolated persistence

The runtime derives three internal roots beneath the configured data directory:

- `generation-queue` for queue and immutable generation-material envelopes;
- `artifact-registry` for revisioned artifact metadata;
- `private-objects` for content-addressed generated bytes.

None of these paths are returned by public runtime summaries or written to normal API responses.

## Provider preflight

The worker refuses to poll the queue when no provider adapter is registered. Every registered adapter must have a server-side credential and must return a capability snapshot whose provider identity, adapter version and fingerprint match the executing adapter.

Credential bindings map a provider identifier to an environment-variable name. The mapping may be configured through `STORYTELLER_WORKER_CREDENTIAL_BINDINGS`; secrets remain in their referenced server environment variables and are never copied into runtime summaries, queue state, artifacts or logs.

The built-in provider registry is intentionally empty until a production adapter passes request, rights, privacy, cost, response-validation and quality review. Enabling the worker before that point fails with `WORKER_PROVIDER_ADAPTERS_REQUIRED` rather than pretending generation is available.

## Bounded execution

The worker validates bounded values for:

- concurrency;
- queue poll interval;
- lease duration;
- heartbeat interval;
- provider timeout;
- outcome history;
- shutdown grace period.

The heartbeat interval must remain below half the lease duration. Provider execution uses the same live clock as heartbeat renewal and terminal queue transitions.

## Process signals

The process subscribes to `SIGINT` and `SIGTERM` only inside the worker lifecycle.

The first signal:

1. stops new claims;
2. allows active jobs to keep renewing their leases;
3. schedules a bounded forced-abort deadline;
4. exits after active jobs finish.

A second signal or an expired shutdown deadline aborts active provider work. Interrupted claims are not falsely completed. They remain recoverable through lease expiry and the queue reaper.

Signal listeners and shutdown timers are always removed after the worker stops or fails.

## No HTTP execution surface

The worker package imports no HTTP server and opens no listening port. The normal API and web application must not import:

- the worker service;
- generation material storage;
- provider execution;
- lease claiming or heartbeat controls;
- private object writes;
- artifact verification or completion.

Operational control belongs to deployment process management and restricted service identity, not a public route.

## Safe operational output

Process output is limited to redacted configuration and lifecycle summaries. It may include mode, concurrency, timing limits, provider count and aggregate job outcomes. It excludes:

- worker and project identifiers;
- data-directory paths;
- credential environment-variable names and values;
- manuscript text and direction;
- voice profile identifiers;
- provider request identifiers;
- private object locators;
- lease tokens and hashes.

## Production migration

The same runtime boundary will later compose:

- PostgreSQL transactional claims and material records;
- private cloud object storage;
- transactional budget reservations before provider execution;
- workload identity and managed secret rotation;
- distributed metrics and tracing without manuscript content;
- autoscaling based on safe queue aggregates;
- dead-letter review and operator recovery.

Provider registration and budget reservation are separate gates. The runtime does not weaken either merely to make the process start.
